## 7. 系统架构图规范

### 7.1 架构图的表达目标

表达结构与主要流向，支持分层、部署讨论与接口划分。

### 7.2 分层原则

常见顺序：接入/表现 → 应用/服务 → 领域/核心 → 基础设施/数据。

### 7.3 数据流表达

数据流宜标注数据摘要；以单向为主。

### 7.4 控制流与调用流

调用用实线箭头；与控制流/数据流在图例区分。

### 7.5 外部系统位置

外部系统置边界外，配色用 §5.9 外部系统色。

### 7.6 逻辑视图与部署视图

逻辑与部署宜分图；同图混绘须标题声明。

### 7.7 嵌入式系统要点

区分 MCU/SoC、RTOS/Linux、驱动、应用；中断/DMA/共享内存仅在有硬件/软件材料时标注。

### 7.8 嵌入式数据与控制通道

传感器 → 驱动 → 中间件 → 应用流向一致；周期参数无材料则 TBD。

### 7.9 Android 分层要点

区分 App、Framework、Native/HAL、Kernel；Binder/HIDL/AIDL 仅在有材料时标出。

### 7.10 Android 应用内分层

App 内 UI/Domain/Data 若绘制，命名须与组件图、时序图一致。

### 7.11 BSP 模块范围

Boot、Clock、Pinmux、驱动、板级配置等须有板级/硬件材料支撑。

### 7.12 BSP 与 OS 边界

标明 Kernel space / User space；驱动加载顺序不确定则标待确认。

### 7.13 总线与协议

I2C/SPI/UART 等与硬件设计一致；主从/速率无材料则 TBD。

### 7.14 安全与信任域

TEE/Secure Boot 须基于安全设计，否则虚线框+待确认。

### 7.15 冗余与高可用

主备/集群仅在架构决策存在时绘制。

### 7.16 架构图图例

须含层定义、箭头含义、颜色语义。

### 7.17 架构反例

全网状互连应删减；空「云」框应命名或 TBD。

### 7.18 PlantUML 架构图绘制指导

#### 7.18.1 基本元素

| 元素 | 用途 |
|------|------|
| `package` | 分层、子系统边界 |
| `rectangle` | 模块、组件 |
| `node` | 物理/逻辑节点 |
| `folder` | 目录/代码组织 |
| `cloud` | 外部系统/网络 |
| `database` | 数据存储 |
| `interface` | 接口契约 |
| `together` | 强制元素水平并排 |

#### 7.18.2 分层架构画法

用嵌套 `package` 表达分层，箭头表达调用方向。示例见 §20.1 模板。

#### 7.18.3 注意事项

1. 分层用 `package` 嵌套，层名与已批准分层表一致；
2. 跨层连线用箭头标注语义（如 `: Binder IPC`、`: ioctl`）；
3. 外部系统用 `cloud` 或灰色弱化；
4. 数据流与控制流用不同箭头：实线=调用，虚线开放箭头=返回；
5. 节点过多时先分组；复杂内容拆分为「总体图 + 局部子图」；
6. 不得混用不同图种语义；
7. 使用 `together` 控制同层元素并排；
8. 推断或未确认模块标注 `（待确认）` 或 `（TBD）`。

### 7.19 架构图检查清单

- [ ] 分层清晰且调用方向合理
- [ ] 数据流/控制流/调用流可区分
- [ ] 无未解释双向箭头
- [ ] 嵌入式/Android/BSP 层与材料一致
- [ ] 推断与 TBD 已标注
- [ ] 与组件图模块名可对齐

## 8. 组件图规范

### 8.1 组件图的表达目标

明确接口契约与依赖方向，细化架构模块。

### 8.2 组件边界

组件对应可构建单元；职责单一。

### 8.3 提供接口

用 lollipop 等表示对外能力；多接口分开绘制。

### 8.4 需求接口

用 socket 表示依赖的外部能力。

### 8.5 依赖方向

依赖虚线箭头指向被依赖方；全文约定一致。

### 8.6 实现关系

实现连线与依赖线型区分。

### 8.7 回调与观察者

回调用虚线+标注或独立接口，不与主依赖混淆。

### 8.8 事件与发布订阅

Publisher → Topic/Bus → Subscriber；异步在图例说明。

### 8.9 循环依赖

须显式画出并在图注登记技术债或待确认解耦。

### 8.10 数据存储组件

库/缓存/文件独立成节点，标注读写意图。

### 8.11 第三方与闭源

用外部配色；推断须说明依据。

### 8.12 协议与端口

HTTP/gRPC 等无材料则 TBD。

### 8.13 变体与 Mock

Mock/Prod 变体须在图例说明。

### 8.14 与架构图对齐

组件名、分层与架构图一致或标待统一。

### 8.15 组件反例

两两实线全网连接——应经接口中介。

### 8.16 评审关注点

接口可测试性、上帝组件、可替换性。

### 8.17 组件图检查清单

- [ ] 提供/需求接口清晰
- [ ] 依赖方向可验证
- [ ] 回调/事件已区分
- [ ] 循环依赖已暴露
- [ ] 无虚构组件
- [ ] 连线从模块边框锚点出发，未贯穿模块主体（见 §10.6.2）
- [ ] 同步/拷贝关系与图例线型一致（见 §10.6.2）
