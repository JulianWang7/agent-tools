## 6. 用例图规范

### 6.1 用例图的表达目标

界定系统边界与对外可观察能力，支撑范围评审与测试划分。

### 6.2 系统边界

边界内为本系统能力；边界外为参与者。
**不应：** 将内部模块画入边界冒充用例。

### 6.3 参与者识别

参与者须为系统外交互方。
**不应：** 将数据库、定时任务画为 Actor（除非确有外部触发语义且材料支持）。

### 6.4 用例命名与动词＋业务对象

用例名必须为**动词＋业务对象**。
**应当：** 「提交订单」「注销会话」。
**不应：** 「订单服务」「OrderModule」。

### 6.5 关联关系

参与者与用例用关联线连接；方向与工具约定在图例统一。

### 6.6 包含关系 include

**语义：** 基用例必然执行被包含片段。
**箭头：** 从**基用例**指向**被包含用例**，stereotype `<<include>>`（base → included）。

### 6.7 扩展关系 extend

**语义：** 条件下追加基用例行为。
**箭头：** 从**扩展用例**指向**基用例**，stereotype `<<extend>>`（extension → base），注明扩展点。

### 6.8 泛化与分包

参与者或用例泛化表达特化关系；用例过多时按域分包或拆图。

### 6.9 不应出现在用例图的内容

数据库表、REST 路径清单、内部类、详细时序。

### 6.10 待确认与范围争议

争议用例标「待确认」或在图注列清单。

### 6.11 配套说明

复杂用例宜有前置条件、主成功场景与关键变体说明（表格式即可）。

### 6.12 反例

将可选「打印小票」标为 include 到「支付」——若非常必然，应 extend 或独立用例。

### 6.13 用例图检查清单

- [ ] 单图单一边界主题
- [ ] 用例名均为动词＋业务对象
- [ ] include 箭头：基用例 → 被包含用例
- [ ] extend 箭头：扩展用例 → 基用例
- [ ] 无内部模块冒充 Actor
- [ ] 无虚构用例或已标 TBD/待确认
- [ ] 与架构图职责范围一致
