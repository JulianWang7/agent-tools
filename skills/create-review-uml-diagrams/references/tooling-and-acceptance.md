## 10. 图示工具使用约束

本章补充 §3.0 工具选型总表中各工具的具体使用约束。

### 10.1 PlantUML 使用要求

UML 图种的首选工具。执行要求：
- 保留 `.puml` 源文件
- 导出 SVG
- 优先官方主题
- 优先 `<style>` 样式块（禁止 `skinparam`）
- 中文字体 Noto Sans CJK SC
- 在 Linux VM 渲染，不在 Windows 本地

### 10.2 Mermaid 使用约束

仅用于 ≤15 节点的简单流程/决策/状态图（草稿阶段）。**不作为正式交付图**。节点拥挤时升级为 PlantUML。

### 10.3 D2 使用说明

默认不使用，优先 PlantUML。

### 10.4 draw.io 使用约束

Draw.io MCP 是正式 UML 图的第二选择：仅在 PlantUML 难以表达或任务明确要求精细手工排版时使用，并记录回退理由。多列每日流程图（泳道）等非 UML 工程流程图可直接首选 Draw.io MCP。导出前必须目视检查所有箭头、锚点、标签和连线。

**规范减负原则**：LLM/程序生成图示时，优先遵守 §10.6.4～§10.6.6 的连线、图面文字和版式要求；版式审校痕迹不得写入图面（见 §10.6.5）。规则发生竞争时，以「垂直入射、空白区折返、紧凑字号」为最高优先级。

**程序生成图示**（如 `gen_diagrams_*.py`、`gen_plantuml_*.py`）**必须**在生成器中固化 §10.6.4～§10.6.6 的适用规则，导出后在 100% 缩放下目视验收。

### 10.5 Draw.io MCP 制图约束

#### 10.5.1 标准图形库选择

- **应当**优先使用 Draw.io 内置 **UML** 图形库；
- 系统架构图**可使用** **Software** 或 **General** 图形库中的标准矩形、容器；
- **不应**使用纯装饰性图形库元素冒充 UML 语义。

#### 10.5.2 UML 图形元素选择

| 图类型 | 应使用的标准元素 |
|--------|------------------|
| 用例图 | 参与者（Actor）、用例（Use Case）、系统边界 |
| 组件图 | 组件（Component）、接口（Interface）、依赖连接器 |
| 时序图 | 生命线、激活、消息、组合片段（alt/opt/loop/par） |
| 架构图 | 容器（Container/Swimlane）、模块矩形 |

#### 10.5.3 形状语义要求

- 每个形状**应当**具有明确的 UML 或工程语义；
- **禁止**使用普通圆形冒充用例、普通矩形冒充组件却不加 UML 构造型；
- 形状选择**应当**与本规范第 6～9 章一致。

#### 10.5.4 连接线与锚点要求

- 连接线**必须**绑定到节点锚点；
- 移动节点后连接线**应当**正常跟随；
- **禁止**使用手工拼接的线段代替标准连接线；
- 连接线**不应**悬空或锚点错位。

#### 10.5.5 图层使用要求

- 可使用图层分离背景容器、主元素、注释和图例；
- 图层**不应**影响元素的可编辑性；
- 正式图**不应**将主元素锁定在不可编辑的背景层。

#### 10.5.6 容器与分组要求

- 系统边界、架构分层、时序组合片段**应当**使用容器表达；
- 分组**应当**保持组内元素可独立编辑；
- **禁止**将多个元素合并为不可拆分的单一形状。

#### 10.5.7 自动布局使用原则

- 自动布局**可以**作为初始排版手段；
- 自动布局后**必须**进行人工式视觉复核；
- 自动布局**不能**作为最终质量保证。

#### 10.5.8 手工布局修正规则

自动布局后**应当**检查并修正：节点重叠、连线交叉过多、标签被截断、容器边界未包裹全部子元素、箭头方向或锚点错误。

#### 10.5.9 文本与节点自适应

- 节点文本**应当**启用合理换行和内边距；
- **禁止**文字超出节点边界；
- 节点尺寸**应当**随文本自适应，而非截断文本。

#### 10.5.10 图示可编辑性要求

- 产出物**应当**为可编辑的 Draw.io 源文件；
- **禁止**将整张图作为不可编辑图片嵌入 Draw.io；
- **禁止**生成无法再次编辑的伪 Draw.io 内容。

#### 10.5.11 Draw.io MCP 禁止事项

1. **禁止**使用普通圆形、矩形随意冒充具有明确 UML 语义的元素；
2. **禁止**使用手工拼接线段代替标准连接线；
3. **禁止**将整张图作为不可编辑图片嵌入；
4. **禁止**使用 Draw.io 默认随机颜色直接作为正式风格；
5. **禁止**为美观改变实际依赖方向；
6. **禁止**在无法确认关系时自行补全连接；
7. **禁止**生成无法再次编辑的伪 Draw.io 内容；
8. **禁止**文字超出节点；
9. **禁止**连接线标签压在线条或节点上；
10. **禁止**为无价值节点浪费图面空间；
11. **禁止**跳过图例（当使用了颜色或线型语义时）；
12. **禁止**不标注图标题就输出正式图。

### 10.6 版式与连线验收要求

本节适用于流程图、组件图、时序图及培训日工程图示的**导出前目视验收**。版式问题默认按 **P1** 处理；仅当导致语义误解时升为 P0。

#### 10.6.1 通用版式

- 主路径与异常/回退路径**应当**分泳道、分列或分路由通道，**禁止**实线与虚线在同一段通道重叠；
- 连接线**不得**穿越非端点模块或节点主体；须通过锚点、waypoint 或图缘绕行；
- 边标签要求详见 §10.6.4；
- 正交连线**应当**保持直角对齐，避免斜线、锯齿与无意义折返；
- 导出 SVG 后**必须**在 100% 缩放下目视检查中文、截断、重叠与大面积空白。

#### 10.6.2 分图种版式

**流程图与追溯图：**
- 主链**宜**单列或单泳道自上而下/自左而右排列；
- 决策菱形「通过」与「失败」**应当**从不同锚点出线（如通过向下、失败向右），避免双标签叠线；
- 回退线**宜**沿图缘或专用异常列折返，**不应**与主链平行重叠；
- 证据/日志节点**宜**置于独立侧列，以虚线引出，**不应**切断主链。

**组件图与架构图：**
- 模块**宜**按层或域分泳道/分栏对齐；
- 头文件、库、实现、驱动、设备产物等依赖**应当**从边框锚点连接，**禁止**竖线或横线贯穿模块中央；
- 同步/拷贝/依赖等语义**应当**用线型区分并在图例说明，标签放在模块间空白区。

**时序图：**
- 消息**必须**按时间自上而下排列，相邻消息 Y 坐标**应当**单调递增且间距一致（建议 ≥ 56px）；
- 自调用**应当**使用右侧（或左侧）折返环，**禁止**在生命线上画过短水平短线冒充自调用；
- 同步调用用实线箭头，返回用虚线开放箭头，须在图例中说明；
- 单张时序图消息数过多时**应当**按场景拆图（见 §5.17）；
- 正式时序图工具约束见 §9.24。

#### 10.6.3 导出两件套

每个正式图示**应当**同时保留源文件 + SVG（详见 §13）。

#### 10.6.4 连线与标签

**正交连线防弯曲（自动生成必检）**：Draw.io 正交连线在 `rounded=1` 时会在折点产生圆弧，导出后常表现为箭头中段 S 形弯曲。**应当**遵守：

| 项 | 要求 |
|----|------|
| 圆角 | `rounded=0`（禁止 `rounded=1`） |
| 锚点 | 显式设置 `exitX/exitY/entryX/entryY`，从边框中点或分岔锚点出线 |
| 折返 | 需要绕行时用 `mxPoint` waypoint，折线仅含 90° 转角 |
| 间距 | 相邻节点垂直间距建议 ≥ 56px，避免过短连线诱发自动折返 |
| 汇聚 | 多线汇入同一模块时**应当**使用不同 `entryY`（如 0.25 / 0.75），避免共线折返 |

**禁止**：无意义中段弯曲、锯齿折返、为避让标签而产生的多余折点（应移动标签或改路由）。

**边标签：**
- 所有边标签**应当**设置白底：`labelBackgroundColor=#ffffff`（可选 `labelBorderColor=none`）
- 标签**应当**置于模块间空白区或线段中段，**禁止**压在模块边框或节点文字上
- 标签与边框冲突时**应当**调整 waypoint/锚点，而非缩小字号或取消白底

**多步骤流程图分列：**
- 主链步骤数 ≥ 8 时**应当**采用双列（或多列）布局，而非单列极长纵排
- 典型分列：左列「实现与构建」、右列「验证与交付」、独立侧列「异常回退」
- 列间衔接用水平正交连线（如 `exitX=1` → `entryX=0`），**不应**强行单列下行导致箭头过短、弯曲增多
- 决策「通过/失败」**应当**从不同锚点出线（通过向下或向右列、失败向异常列）

#### 10.6.5 图面注释与图例措辞

图示画布上的可见文字（图题下方说明、图例、页脚注释）**应当**面向读者解释**业务语义、流程结构或符号含义**，**禁止**写入版式修复、生成器参数、审校过程或缺陷处理说明。

| 允许（语义说明） | 禁止（版式/修复痕迹） |
|------------------|----------------------|
| `实线=主路径 \| 红色虚线=异常/回退` | `rounded=0`、`entryY`、`waypoint`、`jettySize` |
| `绿=ioctl 命令 \| 黄=KV 引擎+mutex` | `边标签白底不压框线`、`避免中段弯曲` |
| `左列实现与构建，右列验证与交付` | `v2 版式修订`、`P1=0`、`ISSUE-xxx 已修复` |
| `自上而下=时间顺序` | `扇出经竖直通道分配`、`程序生成须固化样式` |

版式要求（§10.6.4）**仅**写入本规范、图示审校记录或生成器源码注释，**不应**出现在正式 `.drawio` 导出图面中。手工调整后须删除历史遗留的修复说明文字，再重新导出 SVG。

#### 10.6.6 连线垂直入射与紧凑版式（人工/程序生成必检）

**垂直入射（P0）**

| 项 | 要求 |
|----|------|
| 入射 | 箭头**末段**必须与目标模块边**垂直**：从左右缘进入时末段为水平线，从上下缘进入时末段为垂直线 |
| 出射 | 箭头**首段**必须与源模块边**垂直**，禁止沿模块边线「贴边滑行」再拐弯 |
| 锚点 | 使用 `exitX/exitY/entryX/entryY` 指定边框中点；**禁止**末段与模块边平行重合 |
| 折点 | 需要拐弯时**应当**增加 waypoint，使折点落在**模块间空白区**，而非压在模块边框上 |

**紧凑版式（P1）**

| 项 | 要求 |
|----|------|
| 画布 | 页面尺寸贴合内容，避免大面积留白导致导出后字号显小 |
| 字号 | 节点正文建议 12～13px；节点高度建议 36～44px，与字号比例协调 |
| 边距 | 节点 `spacingLeft/Right/Top/Bottom` 建议 4～8px，文字不贴边框 |
| 间距 | 同列相邻节点垂直间距建议 56px；多列时列间保留 ≥30px 空白区供折返 |
| 导出 | SVG 导出 scale 建议 2，`--border 10`，避免裁切 |

**与 §10.6.4 的关系**：§10.6.4 管「不弯曲」；本节管「垂直入射 + 紧凑比例」。二者**不冲突**，应同时满足。

## 11. 图示评审规范

### 11.1 业务正确性

图示须正确反映范围、结构与交互，不得误导实现或测试。

### 11.2 材料对齐

与需求、接口、代码事实或标注版本一致。

### 11.3 评审输入

待审图、变更说明、依据材料、图例与编号。

### 11.4 评审流程

作者自检 → 同行评审 → 终审（P0 须有人负责）。

### 11.5 记录与追溯

问题须定位到图元素并留结论与日期。

### 11.6 与检查清单关系

第 16 章清单为评审最低检查集。

### 11.7 MCP 草稿评审

MCP 产出按人工材料优先修正。

### 11.8 评审问题等级

| 等级 | 定义 | 示例 |
|------|------|------|
| P0：事实或语义错误 | 导致错误实现、测试范围或接口 | include/extend 方向错误；虚构组件；依赖方向相反 |
| P1 | 主路径可懂但维护困难或难追溯 | 粒度混级；无图例；命名不一致；主链与异常线重叠；连线穿越模块；时序消息顺序难辨；边标签压字 |
| P2 | 排版与措辞建议 | 个别轻微交叉且不影响阅读；缩写未列入图例 |

**不应：** 无材料依据将 P0 降级为 P2。

### 11.9 最终输出约束

正式交付的图示，应当附输出表格供追踪：

| 图号 | 图名 | 工具 | 主题 | 源文件 | SVG | 插入位置 | 验证结果 |
|------|------|------|------|--------|-----|----------|----------|

验证结果仅用：验证通过 / 验证失败 / 待人工确认。失败的图不得插入正式 Markdown。

## 12. 图示版本管理规范

### 12.1 修改触发条件

需求变更、接口变更、架构决策变更、评审 P0/P1 关闭、材料版本更新。

### 12.2 版本号规则

图示版本与文档对齐，建议 `v主.次`；结构变更升主版本。

### 12.3 变更摘要

记录增删元素、关系修正、待确认关闭项。

### 12.4 草稿与基线

草稿须标注「草稿」；基线须 P0 关闭。

### 12.5 禁止建立重复最终版本

同一图编号不得并存多个「最终版」；替代关系须显式指向新编号。

## 15. 图示渲染与验收

### 15.1 PlantUML 环境检查

```bash
java -version 2>&1 | head -1
PLANTUML_JAR=$(find /usr/share /usr/local /opt /home/wanglingqi -name 'plantuml*.jar' 2>/dev/null | head -1)
fc-match 'Noto Sans CJK SC'
which plantuml 2>/dev/null && plantuml -version | head -2
```

### 15.2 PlantUML 渲染命令

```bash
# 方式 A：plantuml 命令行（推荐）
plantuml -charset UTF-8 -tsvg -o ../rendered source/图名.puml

# 方式 B：java -jar
java -jar ${PLANTUML_JAR} -charset UTF-8 -tsvg -o ../rendered source/图名.puml

# 批量渲染
plantuml -charset UTF-8 -tsvg -o ../rendered source/*.puml
```

### 15.3 中文字体配置

中文方框/问号时在 `.puml` 中确保 `<style>` 块内每属性一行、分号结尾（见 §5.13）：

```plantuml
<style>
diagram {
  FontName "Noto Sans CJK SC";
}
</style>
```

### 15.4 draw.io 渲染

```bash
xvfb-run -a drawio --export --format svg --output rendered/图名.svg source/图名.drawio
```

### 15.5 分层验收

自动检查、目视检查、语义/事实检查的判定对象不同，必须分别记录结果；任一层未通过，都不得声明正式图验收完成。

#### 15.5.1 自动检查（可由脚本或 CI 判定）

1. 可编辑源文件与同名 SVG 两件套均存在
2. SVG 文件大小 > 100 B，且可解析并含 `<svg>` 根元素
3. PlantUML 渲染命令退出码为 0，输出中无 `Syntax Error`
4. PlantUML 源文件不含 `skinparam`
5. Markdown 图片引用不使用绝对路径
6. Markdown 图片引用不直接指向 `.puml/.drawio/.mmd/.d2` 源文件
7. 源文件目录、扩展名与 §13.1 的工具目录匹配
8. 图编号、文件名以及源文件链接满足项目可机器校验的命名规则（若项目已配置）

#### 15.5.2 目视检查（必须打开 SVG）

1. 在 100% 缩放下中文显示正常，标题正确
2. 节点无重叠，文字无截断，画布无异常大面积空白
3. 连线方向正确，箭头不重合、不穿越非端点节点
4. 时序消息自上而下排列，自调用折返正确
5. 图例完整，颜色和线型在灰度下仍可区分
6. SVG 在目标 Markdown、HTML 或 PDF 载体中可正常显示
7. Draw.io MCP 回退图已检查锚点、waypoint、标签白底和垂直入射

#### 15.5.3 语义与事实检查（须结合依据材料）

1. 图类型、主题、系统边界与任务目标一致
2. 节点、关系和消息均有需求、接口、代码或评审材料依据
3. 无未标注的虚构内容；不确定项明确标为「待确认」「TBD」或推断
4. 内容与当前源码/文档版本一致，差异与回退理由已记录

### 15.6 验收检查脚本

```bash
#!/bin/bash
# verify-diagrams.sh
SRC_DIR="docs/diagrams"; FAIL=0
echo "=== PlantUML 源文件检查 ==="
for f in "$SRC_DIR"/plantuml/source/*.puml; do
  [ -f "$f" ] || continue
  grep -q 'skinparam' "$f" && { echo "  ⚠ $f 含 skinparam"; FAIL=1; }
done
echo "=== PlantUML 渲染检查 ==="
for f in "$SRC_DIR"/plantuml/rendered/*.svg; do
  [ -f "$f" ] || continue
  SIZE=$(stat -c%s "$f" 2>/dev/null || stat -f%z "$f")
  [ "$SIZE" -lt 100 ] && { echo "  ✗ $f 仅 ${SIZE}B"; FAIL=1; }
  grep -q '<svg' "$f" || { echo "  ✗ $f 无 <svg>"; FAIL=1; }
done
echo "=== Markdown 图片引用检查 ==="
for md in README.md docs/*.md deliverables/*.md; do
  [ -f "$md" ] || continue
  grep -Pn '!\[.*\]\((/home|C:|D:|Y:|Z:)' "$md" 2>/dev/null && { echo "  ✗ $md 绝对路径"; FAIL=1; }
  grep -Pn '!\[.*\]\(.*\.(drawio|puml|d2|mmd)\)' "$md" 2>/dev/null && { echo "  ✗ $md 引用源文件"; FAIL=1; }
done
[ "$FAIL" -eq 0 ] && echo "=== 自动检查通过（仍须完成目视与语义/事实检查）===" || echo "=== 自动检查失败 ==="
exit $FAIL
```

## 18. 常见问题与处理原则

### 18.1 需求不完整

可画边界与 TBD 占位，并列缺口清单；不得画看似完整的虚构细节。

### 18.2 include 与 extend 如何选择

必然复用用 include；条件追加用 extend；不确定标待确认。

### 18.3 能否使用双向箭头

仅材料明确双向协议且图例说明；否则拆单向或标待确认。

### 18.4 多图命名不一致

以已批准接口清单为准统一；暂用「别名（待统一）」。

### 18.5 循环依赖如何处理

组件图显式暴露并登记；解耦方案可 TBD。

### 18.6 时序过长怎么办

按场景或 alt 分支拆图并用编号串联。

### 18.7 用例过多怎么办

按 Actor 或业务域分包/分图。

### 18.8 颜色与模板冲突

以 §5.9 语义色为准并扩展图例。

### 18.9 MCP 与手工不一致

以人工核对与材料为准修正 MCP 草稿。

### 18.10 是否允许中英文混合命名

同一图主语言择一；专有名词/协议可保留英文并列入图例。

## 19. 禁止事项

本章汇总全规范中分散的禁止项，便于索引。凡标注章节号的条目，详细规则见对应章节。

1. **禁止**未分析就出图
2. **禁止**机械生成（不确认图类型/主题/边界/节点/关系就绘制）
3. **禁止**一种工具用所有图（按 §3.0 选型）
4. **禁止**源文件直接做 Markdown 图片（引用 SVG，见 §14）
5. **禁止**绝对路径引用图片（见 §14）
6. **禁止**不保留源文件（见 §13）
7. **禁止**不导出 SVG（见 §13）
8. **禁止**使用 `skinparam`（PlantUML 1.2022+，见 §5.13）
9. **禁止**保留黄色警告条
10. **禁止**只检查源码不检查渲染（见 §15）
11. **禁止**不预览就声称正常
12. **禁止**伪造验证结果
13. **禁止**虚构内容（见 §2.8）
14. **禁止**连线混乱标记完成
15. **禁止**连线重合标记通过
16. **禁止**普通图用状态色（见 §5.11）
17. **禁止**颜色无图例（见 §5.14）
18. **禁止**自动 Git 提交（须人工确认后提交）
19. **禁止 Windows 本地渲染 PlantUML**（须在 Linux VM 执行）
20. **禁止**未评估 PlantUML、未记录回退理由就使用 Draw.io MCP 生成正式 UML 图（见 §3.0、§9.24）
21. **禁止**以上未列出的 Draw.io MCP 制图禁止项，详见 §10.5.11（共 12 条）
